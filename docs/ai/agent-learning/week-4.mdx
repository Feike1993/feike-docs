# Week 4 · 工程化、评测与试跑

主题：从「能演示」到「别人愿用」；补齐评测、安全与证据。方法回顾：[Agent 怎么学](./how-to-learn.mdx)。

**本周出口**：≥30 条 Golden Set；轨迹与成本可查；高风险动作有人工确认；≥3 人试跑；Badcase 复盘可放进简历叙述；MCP 最小实验跑通（加分项按计划必做）。

## D22–D23 · 评测与成本

**上午精读**

- Anthropic：测量再迭代；关注 outcome（环境最终状态），不只看模型「说了什么」
- 加深：JavaGuide AI 应用评测体系（Golden Set、LLM-as-Judge、Trace）

**下午动手**

- Golden Set 扩到 **≥30**（真实任务语气，含会失败的题）
- 固定对比：模型 A/B、Prompt 版本、工具 description 版本
- 日志级 Token、步数、耗时、工具失败率（可先文件/表，不要求完整看板）

**对照 / 日记**

- 选 3 个 Badcase，写清是召回、工具、Prompt 还是停止条件问题
- DoD：任意一次改动都能回答「哪几题变好/变坏」

## D24 · 安全与治理意识

**上午精读**

- Prompt 注入（直接/间接）、工具越权、敏感数据
- 加深：JavaGuide LLM/Agent 安全、大模型网关概念（限流、fallback、审计）

**下午动手**

- 工具权限分级：只读 vs 写；写操作走「草稿 + 人工确认」
- 注入样例进评测集；确认 System 边界与工具白名单有效

**对照 / 日记**

- 列出若上生产还缺的网关能力（本月可只列清单）
- DoD：演示路径上没有「模型一句话直接删库/退款」

## D25 · MCP 最小实验

**上午精读**

- [MCP 官方](https://modelcontextprotocol.io/)：解决什么问题；与 Function Calling 的关系
- Spring AI Reference 中 MCP 相关章节（若版本已收录）

**下午动手**

- 跑通一个本地 MCP Server（官方示例或自写一个只读工具）
- 从 Agent / 客户端侧发现并调用一次；记下传输方式（stdio / Streamable HTTP 等）

**对照 / 日记**

- 写五句说明：MCP vs 进程内 `@Tool` 各适合什么
- DoD：最小闭环可演示；不做企业 SSO/审计全集

## D26–D27 · 试跑与复盘

**上午**

- 准备试跑脚本：任务说明、已知限制、如何反馈失败

**下午**

- **3～5 人**真实试跑；收集失败样本
- 补拒绝策略、升级路径、人工接管文案
- 写 Badcase 复盘 + 架构说明（选型、为何单 Agent、评测证据）

**日记**

- 简历可讲三点：问题边界、关键取舍、一条有数据的改进故事

## D28 · 总复盘

对照 [一个月验收清单](./resources.mdx#一个月验收清单) 打勾。缺项记下第 2 个月优先序。

:::tip[结束标准]
不是「学了很多概念」，而是：用户发起任务 → Agent 取上下文 → 选工具 → 产出可验收结果 → 失败能解释或升级给人 → 你能从日志回放全过程。
:::
