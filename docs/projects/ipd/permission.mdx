# 权限体系

权限中心（`base-permit-server`）管组织、角色、菜单/按钮模型。IPD 是 **消费者 + 单据授权落地**：保存单据时向中心要行权限元素，查询时用拦截器改 SQL；项目页上的字段读写另有资源权限表。

## 行权限（主路径）

1. 保存项目/任务等 → `BillDataGrantHelps` / `GrantServiceImpl` 调 Feign `getRowPermitElementsByData`
2. 结果写入 `BillGrantUserBase` 一类授权表
3. 列表查询走 `DataScopeInterceptor`，把 `${dataScopeParam_*}` 换成 `bill_code in (...)`

这是「运行时动态判定」在本仓最实的一层：同一张项目表，不同人看到不同行。

## 列权限与按钮

`BasePermissionClient` 有：

- `getColPermitColsByData` 列权限
- `getButtonPermitByAccount` 按钮权限

列权限在业务 Service 里几乎没有调用点，能力停在 Feign 客户端。按钮/菜单树主要在权限中心和 SSO，IPD 不维护完整菜单引擎。

## 项目资源字段

`IpdResourceAuthority*`：按项目校验字段码（如 `project_status`、`total_project_budget`）的读写。这是页面级「这块能不能改」，和行级「这行能不能看见」叠在一起。

## 本地 grant 模块

`GrantController` 做单据授权维护。`IpdResource*` 管页面资源。不要把「菜单 / 按钮 / 行 / 列」四层都说成 IPD 自己实现了一遍；**行 + 项目字段**在本仓，**菜单/列**在权限中心，列 API 尚未铺开。
