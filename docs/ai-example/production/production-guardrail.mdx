# 生产护栏与 Citation

对应生产路径 `com.feike.ai.production.guardrail`。教学[输出护栏](../principles/quality/guardrail)说明了词表检查；工业链路还必须说明**检查放在哪里、失败如何成为稳定契约，以及检索回答怎样避免“看似有引用”**。

## 流程步骤

1. **规范化词表**  
   启动时把 `ProductionProperties.security.denyWords` 交给 `DenyWordChecker.normalize`；不要让每个 Controller 各自 `contains`，否则大小写和空白规则会漂移。

2. **输入先短路**  
   Chat / Agent 编排先执行 `checkInput(question)`。命中即抛 `input_deny`，不创建模型调用、不写会话终答；HTTP 层映射为 `422`。

3. **检索结果约束引用**  
   当本次 `sources` 非空，`checkCitations(answer, sources)` 解析答案中的 `[C#]`，至少一个编号必须落在本次检索集合。空检索的拒答由[生产 RAG 默认](./production-rag)负责，不把“没有 sources”误判成 citation 失败。

4. **输出在发布前再拦一次**  
   `checkOutput(answer)` 放在写入 `done`、落会话历史之前。流式路径也应先完成受控答案再发送终态；不能在 `done` 后才发现违规。

5. **同一失败面与指标**  
   输入、输出和 citation 失败均增加护栏计数。客户端按 `input_deny` / `output_deny` / `citation_missing` 展示；详见[错误契约](./error-contract)。

## 应用场景

- 公开问答入口要在调用 LLM 前拒绝明显不允许的请求。
- RAG 回答需要让用户能回到本次检索证据，而非接受模型编造的编号。
- 压测与 E2E 需要通过无模型的 `422 input_deny` 覆盖保护路径。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 输入、输出分两次检查 | 覆盖面完整；编排要明确两处调用点 |
| Citation 只在有 sources 时要求 | 空检索不混入另一类失败；调用方仍要处理拒答 |
| 失败走 422 | 网关和客户端可区分校验失败与 429 / 503；不再“一律 200” |
| 记录计数，不记录问句原文 | 可观测且少泄露；精确排查需看受控日志 |

## 刻意不做

- 不把演示词表包装成完整的内容安全产品  
- 不声称 citation 校验等于事实正确性  
- 不让护栏失败退化为“仍生成、只在页面显示警告”
