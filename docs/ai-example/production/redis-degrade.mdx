# Redis 失败取向

工业链路共用一条 Redis，但**不能共用一种失败语义**。源码把「为什么和 SSE 相反」写在会话锁的类注释里；本页把它收成一张总图，避免每篇原理页重复同一段话。

## 怎么选

| 依赖 | Redis 挂了 | 原因 | 正确性落点 |
| --- | --- | --- | --- |
| 令牌桶 | 放行 | 限流是保护模型配额的优化 | 配额与账单在 Provider 侧 |
| 会话锁 | 放行 | 为锁停掉问答不划算 | Postgres 主键与 turnId |
| Idempotency-Key | 放行 | GET SSE 本就不走这里 | 客户端可重试；runId 续传 |
| SSE 事件日志 | 503 | 续传是对外承诺 | 没有日志就没有回放 |
| 信封 / HMAC | 503 | 解不开不能签发或校验 JWT | 密钥根本不可用 |
| 输入输出护栏 | 422（与 Redis 无关） | 能被说服关掉的护栏等于没有 | 词表 + citation 校验 |

`RateLimitExceededException` 必须原样抛出，不能被外层 `catch (RuntimeException)` 当成 Redis 故障吞掉后 fail-open。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 按承诺分级 | 实现者每次都要选边；不能抄「统一熔断」 |
| 限流异常不得被吞 | 多一层 catch 纪律；否则 fail-open 会放掉真 429 |
| 护栏独立于 Redis | 词表误报时仍 422，与基础设施健康无关 |

## 刻意不做

- 不把所有 Redis 调用包成同一种 CircuitBreaker 策略  
- 不在故障时切换到进程内锁还对外声称「跨实例互斥仍然成立」
