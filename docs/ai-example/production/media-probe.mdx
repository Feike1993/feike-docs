# 媒体探针

对应生产路径 `com.feike.ai.production.media`。多模态很容易在探针、问答、Agent、语音四条路上各写一套上限。工业链路强制共用一把尺子，并且**不把 blob 写成长期记忆**。

## 流程步骤

1. **探针不打模型**  
   `POST /media/probe` 无 JWT → 401；`.exe` → `media_unsupported`；超 `PRODUCTION_MEDIA_MAX_BYTES` → `media_too_large`；合法小文件返回 `{ mime, bytes, sha256 }`。

2. **同一上限**  
   默认最多 3 张图、2 份文档、单文件 2MiB。超件 `media_too_many`，在进 LLM / Agent 循环之前 422。

3. **不落盘**  
   不写文件系统，不进 pgvector。审计 `media.probe` 只有 sha256。刷新后再问，历史里是占位文本，不再带原图。

4. **文档与 OCR**  
   可抽文本的 pdf/txt/md/docx/xlsx 走抽取器。扫描 PDF 字太少时渲染页，用现有 VL **只转写**；渲染位图用完即弃，不塞进本轮识图 Media。

5. **语音附录**  
   ASR/TTS 手写 HTTP，不打开 OpenAI Audio 自动配置（那会把文生图/音频自动配置搅进来）。TTS 空文本 400，违禁词 422 `input_deny`。音频不写入会话。

## 应用场景

- 本轮看图 / 带文档，但不做「知识库上传」。
- CI 要断言鉴权与 mime，不能调用视觉模型。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 不落 blob | 隐私与备份简单；无法「再看上次那张图」 |
| 探针与问答共用 Inspector | 行为一致；Inspector 会变胖 |
| 手写语音 HTTP | 避开错误的 Spring AI 自动配置；自己维护客户端 |

## 刻意不做

- 不做知识库上传后台  
- 不把附件写入向量库当长期记忆  
- 默认 Playwright 不打 VL / ASR / TTS

Agent 有图时为何先转写：见 [Agent 看图](./agent-vl)。
