# JWT 与显式 Principal

对应生产路径 `com.feike.ai.production.auth`。工业接口要身份和租户，教学路径必须继续匿名。SSE 跑在虚拟线程上，不能把身份藏在 `SecurityContextHolder` 里碰运气。

## 流程步骤

1. **谁被 Filter 看见**  
   路径不含 `/api/v1` 则 `shouldNotFilter`。`POST /api/v1/auth/token` 放行以便换令牌。Prometheus 刮取走独立 `PRODUCTION_METRICS_TOKEN`，不复用用户 JWT。

2. **缺密钥先 503**  
   信封还不可用时不进入「没带令牌」分支，避免把配置问题伪装成登录失败。

3. **校验后写入 request**  
   HMAC 来自信封里的 `jwt.hmac`，不写在配置文件明文。成功则 `request.setAttribute(ProductionPrincipal.ATTR, principal)`，并往 MDC 放 tenant / sub。

4. **控制器显式下传**  
   `JwtAuthFilter.require(http)` 取出 Principal，作为参数传到 Chat / Agent。SSE worker 用的是这个对象的副本语义，不靠线程局部存储。

5. **租户隔离的对外形状**  
   读到不属于自己的 session / run 时抛 `SessionNotOwnedException`，HTTP 与 SSE 都落成 `session_not_found` **404**，不暴露存在性。

## 应用场景

- 同一进程里样例匿名、工业接口有租户。
- 流式接口用虚拟线程，不能假设 `SecurityContext` 会传播。
- 跨租户探测必须得到与「不存在」相同的 404。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 只武装 /api/v1 | 课程不被挡住；身份边界靠路径而不是注解扫全包 |
| 显式参数而非 Holder | 虚拟线程安全；每个入口多写一行 require |
| 错租户 404 | 不给存在性泄漏；排障时要靠本租户的 sessionId |
| 刮取用独立 Bearer | 浏览器 JWT 刮不到 Prometheus |

## 刻意不做

- 不做 OAuth / OIDC / 企业 IdP  
- 不把 MCP Bearer 当成用户身份（那是工具进程凭证）  
- 不在 SSE 里重新解析一次 JWT 当唯一真相（以 request 下传为准）
