# 双实例 HA

对应 Compose 的 `java-a` / `java-b` 与 `InstanceIdFilter`。锁和 SSE 续传从第一天就是为跨进程设计的；第六阶段只是把第二份 Java 立起来，证明它们不是单机幻想。

## 要证明什么

| 项 | 通过标准 |
| --- | --- |
| 双进程 | Compose 同时有 java-a、java-b |
| 身份可辨 | `/api/v1/**` 带 `X-Instance-Id` |
| 会话锁 | 同一 sessionId：A 持锁打 B → 409 `session_busy`，且两台实例头不同 |
| SSE 续传 | A 写 sse-probe，B 用 `Last-Event-ID` 回放到含探针事件 |
| Nginx | `:8088` least_conn，不要绑死一台 |

## 流程步骤

1. **探针代替真 Chat**  
   护栏短路打不到锁；真占锁必须走过检索/生成。`lock-probe` 只占 Redis；`sse-probe` 只写假事件。这是测试设计，不是偷懒。

2. **JWT 跨实例**  
   HMAC 在 Postgres 信封里，两台读同一把钥匙。A 换的令牌 B 认。

3. **不要用 Vite 验 HA**  
   `pnpm dev` 没有双实例反代。整栈入口是 Nginx。对照脚本直打两台 Java 的映射端口。

4. **配置配对**  
   `PRODUCTION_SESSION_LOCK=memory` 或 `PRODUCTION_EVENT_LOG=memory` 时，跨实例演示无意义。

## 应用场景

- 要向评审证明锁和续传不是单进程 Map。
- 排查「刷新后 SSE 没了」时先看是不是打到了另一台、以及事件日志是不是 Redis。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 探针不打 LLM | HA 可进日常；不证明真实 TTFT |
| 实例头只打 /api/v1 | health 保持干净；看头必须走工业路径 |
| 手册留在源码仓 | feike-docs 讲 why；命令以源码仓为准 |

## 刻意不做

- 不在本页粘贴可过期的 curl 长脚本  
- 不做三机房 / 自动故障转移产品  
- 不把 Vite preview 当成 HA 入口
