# 生产 Agent 工具策略

对应生产路径 `com.feike.ai.production.agent`。教学 [ReAct](../principles/react-agent) 已经把 Loop 讲清。生产 Agent 多出来的工业点是：**模型根本不该看见它调不了的工具**，以及默认测试不许打真循环。

## 流程步骤

1. **角色 → 允许集合**  
   USER：`search_kb` / `add` / `get_weather`。ADMIN 额外 `rebuild_index`。集合在发 schema 前算完。

2. **闭包里仍带 Principal**  
   即使模型胡乱点名，执行入口再查一次 `ToolPolicy.allows`。第一道过滤减少胡点；第二道防止漏网。

3. **探针**  
   `POST /agent/tool-probe` 走同一套策略，不创建 run、不调模型。alice 探针 `rebuild_index` → `denied:true`。这是默认 Playwright 能覆盖策略的原因。

4. **审计**  
   `action=agent.tool`，字段是工具名和是否拒绝。问题原文只存 sha256（见 [可观测与审计](./ops-audit)）。

5. **与问答共用锁和落库**  
   多出来的是 `step` 事件。Loop 本身不在本页展开。

## 应用场景

- 生产 Agent 要把危险工具（重建索引）从 USER schema 里拿掉。
- CI 要证明策略，但不能调用 Chat。
- 对照教学 ReAct：那里没有按角色裁剪。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 过滤发生在 schema 前 | 模型更老实；改角色必须同时改清单 |
| 探针不执行 | CI 便宜；真副作用仍要人工 / @keys |
| 不问句原文 | 隐私更好；出了问题要对着 sha256 查 |

## 刻意不做

- 不重写 ReAct Loop 算法  
- 不把有副作用的真实外部工具接到演示集  
- 默认 E2E 不打 `/agent/stream`

看图时为何不能把 VL 挂进工具循环：见 [Agent 看图](./agent-vl)。
