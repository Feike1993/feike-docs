# 教学 / 工业双平面

对应生产路径 `com.feike.ai.production`。教学场保持「点开即跑」，工业级走另一条必须显式打开的入口，两条 HTTP 路径互不重叠。

## 流程步骤

1. **路径分开**  
   样例继续挂在 `/chat`、`/rag`、`/agent` 等。工业入口统一 `/api/v1/**`，由 [`ProductionChatController`](https://github.com/Feike1993/ai-example) 一类控制器承接。前端教学场是 `/`，工业页是 `/industrial.html`。

2. **开关关则零 Bean**  
   [`ProductionConfiguration`](https://github.com/Feike1993/ai-example) 按 `app.production.enabled` 装配。服务层用 `@Bean` 显式声明而不是满世界 `@Component`：关掉时不必去翻十几个条件注解。控制器是例外——Spring MVC 只给 `@Controller` 建路由，所以控制器自己带同一开关。

3. **启动失败 vs 请求失败**  
   缺 `PRODUCTION_KEK` 或 Redis 暂时不可用时，进程仍应起来（教学样例还能点）。`/api/v1` 在密钥不可用时返回 503，而不是让整个 Spring Boot 起不来。

4. **表结构按工业增量走 Flyway**  
   `V2` 工业会话，`V3` 信封密文与审计，`V4` Agent 审计列。教学会话表仍由更早的脚本接管，不要把两套会话写进同一张表。

## 应用场景

- 同一仓库同时承载 cookbook 与「能讲清楚生产取舍」的 `/api/v1`。
- 要把鉴权、多实例、密钥信封从样例里拆出去，又想保留一键可跑的教学 Tab。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 显式开关默认关 | 升级不会突然暴露 /api/v1；要用必须写 enabled=true |
| 服务用 @Bean 不用扫描 | 「关掉就没有」在一个文件里看得见 |
| Redis 不挡启动 | 教学仍可跑；工业接口在请求期 503 |
| 不把教学路径锁上 | 课程优先；身份只存在工业平面 |

## 刻意不做

- 不把教学样例改成必须登录  
- 不做知识库上传后台 / 多租户产品面  
- 不把装配开关拆成一篇独立水文（已写在本页）

同一条 Redis 上的 fail-open / fail-closed 对照见 [Redis 失败取向](./redis-degrade)。限流算法见 [Redis 令牌桶](./redis-token-bucket)。
