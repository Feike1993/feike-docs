# 错误契约

对应生产路径 `com.feike.ai.production.web`。教学样例可以「JSON 里带个 ok 字段」。工业 `/api/v1` 已经靠 401 / 409 / 422 / 429 / 503 工作，成功体也不套 `data`。

## 架构图

业务失败进 ExceptionHandler，目录化成 `ErrorCodeEnum`，再分成 HTTP `{code,message}` 与 SSE `error` 事件。两条出口同名，方便对照。

## 流程步骤

1. **目录化**  
   机器码给排障和前端分支（`session_busy`、`input_deny`），中文给用户。成功响应不走这套枚举。

2. **Filter 与 Advice 同一 JSON**  
   `JwtAuthFilter` 自己 `writeJson`，因为 Filter 进不了 `@RestControllerAdvice`。字段仍是 `code` / `message`。

3. **常见状态**（不必记全表，以枚举为准）  
   401 缺/坏令牌；403 非 ADMIN 重建；404 错租户会话与 run（不暴露存在性）；409 `session_busy` 与 Idempotency-Key 冲突；422 护栏与媒体；429 令牌桶；503 密钥或事件日志。

4. **幂等**  
   HTTP `Idempotency-Key`：同一租户同一 key 只接受同一份请求体，冲突 409。Redis 挂了 fail-open。GET SSE 不走这里，断线续传已经有 `runId`。

5. **未知异常**  
   打 error 堆栈；对外通用中文 `internal_error`。不要把异常类名送进工业页。

## 应用场景

- 工业 API 要给压测、E2E、浏览器三套客户端同时用。
- 需要把限流、护栏、鉴权从「业务失败字符串」里拆开。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 真 HTTP 状态 | 与部分国内「一律 200」习惯冲突；和基础设施友好 |
| code 与 SSE 同名 | 两处要一起改 |
| 未知异常藏细节 | 排障靠日志；用户看不到类名 |

## 刻意不做

- 不套统一 Result / data  
- 不把教学样例改成这套错误码  
- 不在 404 上对错租户使用 410 来「更精确」（会暴露存在性）

令牌桶如何写 Retry-After：见 [Redis 令牌桶](./redis-token-bucket)。
