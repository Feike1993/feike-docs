# 异步入库

对应生产路径 `com.feike.ai.production.rag.ingest`。教学 ingest 是同步、匿名、当前请求线程里建完索引。工业重建语料是管理员任务：要排队、要跨实例只做一次、没 Embedding Key 时也不能把 HTTP 挂住。

## 流程步骤

1. **权限在投递前**  
   非 ADMIN → `ingest_forbidden` 403。不要先入队再在 worker 里拒绝，否则队列里会堆没有身份的任务。

2. **202 而不是 200**  
   立刻返回 `jobId` 与 `queued` / `running`。消费很快时轮询也可能已经是终态。

3. **两份存储**  
   Stream：还没 ACK 的活。Hash：`chunkCount`、`errorMessage`、`instanceId`。XREAD 看不见已完成任务，前端却还要展示。

4. **只消费一次**  
   同一 `jobId` 的 `instanceId` 不应在两次查询间从 a 跳到 b。`PRODUCTION_EVENT_LOG=memory` 时退回进程内队列，这条保证失效。

5. **没有 Key 也要把管道跑完**  
   任务仍投递，终态 `failed` 带错误文案。这已经证明可观测；HTTP 一直挂起才是失败。真建索引要 Embedding，标成「本机选跑」。

## 应用场景

- 重建生产语料不能占用问答请求线程。
- 要演示「没 Key 时管道仍然可观测」。
- 对照教学同步 `POST /rag/ingest`：那条路径不要拿来做工业验收。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 202 + 轮询 | 客户端多一轮；避免网关超时 |
| Stream / Hash 拆开 | 多一个 key 空间；查询终态不必扫 Stream |
| 无 Key 也入队 | 可观测；会在失败队列里留下演示噪音 |

## 刻意不做

- 不做通用任务框架 / 重试死信产品  
- 不把教学同步 ingest 改成 202  
- 知识库上传后台明确不做（见源码 backlog）
