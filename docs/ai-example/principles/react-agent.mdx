## 流程步骤

1. **Agent = 会多步决策的 Chat + Tools**  
   相对单次 Tool Calling，Agent 在任务「未完成」时会继续 Reason → Act，直到给出最终答案或触达终止条件。

2. **Perceive → Reason → Act → Observe**  
   用户输入进消息列表；模型判断要不要工具；执行工具；观察结果写回消息，再进入下一轮推理。

3. **Memory 第一期 = 当轮消息列表**  
   无跨会话外存；每一步都基于不断变长的 messages，历史工具结果也在同一列表里。

4. **终止条件要显式**  
   无 `tool_calls`（任务完成）、达到 `maxSteps`（防死循环）、工具错误文本让模型降级，而不是无限重试同一调用。

5. **显式 Loop vs Framework**  
   手写 Loop（如 `ReactAgentLoop`）可审计每一步；`ChatClient.tools` 托管适合业务快速接入，轨迹不如显式清晰。

6. **Agent ≠ 工作流**  
   工作流路径预先写死；Agent 下一步由模型选择。开放任务用 Agent，确定性任务用工作流。

7. **流式 = 同一 run + Progress**  
   同步与流式共用完整多跳；阻塞循环放在 `Flux.create` + `boundedElastic`，边执行边推 SSE（`tool_call` / `tool_result` + `usage` / `done`），避免占住事件循环。

## 应用场景

- 调研、排障、多步查询后再总结。
- 需要中途根据工具结果改策略的助手。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 手写循环 | 教学清晰；比框架魔法更好对照 |
| maxSteps | 防无限 tool；触顶需产品侧收束文案 |
| 终答 vs tool_call | 无 tool 文本才进 Final |

## 刻意不做

- 不上完整工作流引擎 / LangGraph 作为 Java 主路径  
- 不把 Agent 等同于「多轮 Chat UI」
