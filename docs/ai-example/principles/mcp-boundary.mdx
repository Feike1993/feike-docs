## 流程步骤

1. **先有工具，再有协议外壳**  
   仍是 `@Tool` / JSON Schema；MCP Server 把同一批工具用 JSON-RPC 暴露出去，Client 发现后挂到 `ChatClient`。

2. **远端与同进程并存**  
   主应用同时备好 `SyncMcpToolCallbackProvider` 与 `mcpServerTools`；按运行时 mode 选用。remote 需先起 `mcp-server`（8081）。

3. **对照本地 Tool Calling**  
   `POST /tools` 是进程内 `.tools(bean)`；`POST /mcp/chat` 的 `toolNames` 来自当前 mode 的工具源。

**Bearer（sample 19）**：Streamable HTTP 需最小凭证约定——Server 校验 `Authorization: Bearer`，Client 注入同密钥；无/错 → 401。inprocess 不走 HTTP，不要求 Bearer。

## 应用场景

- 把内部工具以标准协议提供给 IDE/Agent Host。
- 本地开发用 inprocess，联调用 remote Server。

## 设计取舍

| 选择 | 取舍 |
| --- | --- |
| 先 inprocess | 降低协议学习成本；无真实网络边界 |
| 懒连 remote | 启动不拖垮；连不上变接口 503 |
| Bearer 单独样例 | 协议层与业务鉴权解耦（非 OAuth 产品面） |

## 刻意不做

- 不在构造期强连旁进程  
- 不把 MCP 当成唯一 Agent 总线  
- Bearer 样例不引入 OAuth/JWT 多用户 ACL
