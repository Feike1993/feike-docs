# Flink 怎么学

方法比书单更重要。这一页定规矩；具体日程见 [Week 1](./week-1.mdx)～[Week 4](./week-4.mdx)，
链接见 [一手资料与官网](./resources.mdx)。

## 目标分层

| 层级 | 你会什么 | 本月是否够 |
| --- | --- | --- |
| 会写作业 | 能把 DataStream / SQL 拼出来，本地跑出结果 | 不够 |
| 会写对的作业 | 时间语义、状态、并行度都用对；知道数据会乱序、会迟到 | 中间态 |
| 会运维作业 | 状态不爆、checkpoint 做得出、故障能恢复、端到端不丢不重 | **一个月终点** |

:::tip[一句话]
会写 Flink 作业 ≠ 会写对的作业 ≠ 会运维一个线上 Flink 作业。
本月的落点在最后一层——**能对状态大小、checkpoint 耗时、端到端一致性负责**。
:::

## 学习顺序（硬规则）

1. **先搞清 2.x 与 1.x 的断裂，再学新东西**

   Flink 2.0 是一次**破坏性**大版本：`SourceFunction` / `SinkFunction` / DataSet API 被整体移除，
   `env.setStateBackend()` 也没了。你现有的 1.x 经验里有一部分**已经作废**，
   先花半天把差异清单过一遍（见下方 [破坏性差异清单](#2x-与-1x-的破坏性差异清单)），
   否则会一直在「为什么我这么写编译不过」上打转。

2. **先手写一遍新 Source 接口，再用现成连接器**

   真实项目当然用官方 Kafka 连接器，但**手写一次** FLIP-27 的
   `Split / Enumerator / Reader` 三件套，你才会明白：
   为什么扩并行度能重分配分区、为什么 checkpoint 里存的是 offset、
   为什么「读完了要显式通知 reader 没有更多分片」这种细节会决定作业会不会挂住不退。

3. **时间语义必须动手，不能只读**

   水位线的定义一句话就讲完（`见过最大事件时间 - 容忍乱序`），但**直觉建立不起来**。
   本项目的做法是：同一批乱序数据，用两种容忍度各跑一遍，
   对比窗口收到的条数——**差异自己跑出来一次，胜过读十篇讲解**。

4. **每加一层复杂度，都要能用「不这么做会怎样」解释**

   比如「为什么要 keyBy 才能用 Keyed State」「为什么窗口会重复输出」
   「为什么开了 checkpoint 还要管 sink 的事务」。答不上来的，就是还没真懂。

## 每天 8 小时怎么切

| 块 | 时长 | 做什么 | 不做 |
| --- | --- | --- | --- |
| 精读 | 3h | Overview → Concepts → 本周章节；记边界与反例 | 同时开 5 个标签页漫游 |
| 动手 | 3h | 跑通本周例子 → 接到你自己的数据形状上 | 只看不写 |
| 对照 | 1.5h | 改一个参数 / 换一个后端 / 调并行度，记录输出差异 | 无记录地刷源码 |
| 日记 | 0.5h | 今日卡点、失败样例、明日第一件事 | 空写「学习了 Flink」 |

时间不够时：**砍精读第二篇与加分项，保住动手 DoD**。

## Java 老经验怎么重新定价

**这不是从零学一门新技术，是把已有能力映射到一套新坐标系里。**
你熟悉的东西大部分仍然有用，但对应关系变了：

| 你熟悉的 | 在 Flink 里对应 | 关键差异 |
| --- | --- | --- |
| Spring Boot 无状态服务 | Flink 作业 = **有状态的长驻进程** | 服务随时可重启；作业重启要恢复状态 |
| MySQL / Redis 存状态 | Keyed State + State Backend | 不用自己处理并发——同一 key 必在同一实例 |
| 数据库事务 / 幂等键 | Checkpoint + 两阶段提交 | 快照一致 ≠ 端到端一致，还要 sink 配合 |
| MQ 消费位点提交 | checkpoint 里的 source offset | 位点和状态在**同一个快照**里，天然对齐 |
| 线程池 + 有界队列 + 拒绝策略 | 并行算子实例 + 网络缓冲 | 队列打满的表现是**反压**，不是抛异常 |
| XXL-JOB / 定时任务 | 事件时间 Timer、窗口触发器 | 定时器跟着**数据时间**走，不是墙钟 |
| 日志 / 链路追踪 / 指标 | Metrics + Checkpoint 历史 + 反压监控 | 排查问题先看 checkpoint 再查日志 |
| 分库分表 / 分区键 | `keyBy` + 并行度 | key 倾斜 = 某个实例先成为瓶颈 |
| **你的 1.x Flink 经验** | 需要**部分作废重学** | 见下方破坏性差异 |

:::danger[思维转变的一句话]
从「请求-响应、无状态、同步」切到「**事件驱动、有状态、长驻、带时间语义**」。
:::

## 2.x 与 1.x 的破坏性差异清单

这份清单值得单独记住——**它是你 1.x 经验里唯一「不再是资产而是负债」的部分**：

| 变更 | 影响 |
| --- | --- |
| `SourceFunction` / `SinkFunction` / Sink V1 **全部移除** | 旧的 `addSource` / `addSink` **不可用**，必须改用 `env.fromSource()`（FLIP-27）与 `stream.sinkTo()`（FLIP-191/372）。**这是迁移的最大冲击** |
| **DataSet API 已移除** | 批处理改用 DataStream + BATCH 模式，或直接用 Flink SQL |
| **`env.setStateBackend()` 已移除** | 状态后端改成配置项 `state.backend.type`；增量 checkpoint 也变成独立配置 |
| `CheckpointConfig.setCheckpointStorage()` 已移除 | 快照位置改成配置项 `state.checkpoints.dir` |
| `RuntimeContext.getIndexOfThisSubtask()` 移走 | 需经 `getTaskInfo()` 取 |
| 默认状态后端变为 `hashmap` | 旧的 `Memory / Fs / RocksDB` 三件套没了 |
| Scala DataStream / DataSet API 移除 | 只能写 Java |
| `flink-conf.yaml` → `config.yaml`；per-job 部署模式移除；Java 8 不再支持 | — |

> **核对来源**：[Flink 2.0 Release Notes](https://nightlies.apache.org/flink/flink-docs-release-2.3/release-notes/flink-2.0/)。
> 本清单里带「已移除」的条目都在本项目代码里实测过——编译器会直接告诉你。

## 怎么读官方文档

固定路径，减少迷路：

```text
Learn Flink（动手教程） → Concepts（概念） → DataStream / SQL API → Ops（运维）
```

- 每个官网从哪一页开始：见 [一手资料与官网](./resources.mdx)。
- **中文官方文档在维护且已覆盖 2.x**，可以放心用（见 resources 的说明）。
- 版本敏感：Flink 2.x 与 1.x 的文档差异极大。**看资料前先确认版本号**，
  搜到 1.x 的博客要能自己判断哪些 API 已经没了。
- 遇到 `setStateBackend` / `addSource` / `DataSet` 这类写法，基本可以判定资料过时。

## 常见学法误区

:::danger[容易白费一个月的做法]
- **照着 1.x 教程写 2.x 代码**：`addSource` 编译不过就到处找 workaround，
  而不是意识到接口被整体换掉了。先过一遍破坏性差异清单。
- **只读不跑时间语义**：水位线、窗口触发、迟到数据的文档看懂了，
  但没有一次「改容忍度 → 看条数变化」的对照实验，面试一问就露馅。
- **把 checkpoint 当成「不丢不重」的全部**：checkpoint 保证的是作业内部状态一致；
  端到端还要 source 位点 + sink 事务配合。这是最常见的认知缺口。
- **不关心状态大小**：本地跑几十条数据永远没问题，
  真实场景 key 基数一大就可能状态爆炸。要在本地就建立起「状态是有成本的」意识。
- **只在本地跑，不碰集群**：本地 MiniCluster 与真实集群在
  部署模式、资源、并行度、jar 依赖上差别很大。第四周务必提交一次真实集群。
:::
