# Week 3 · 状态与容错

主题：**这是「会写作业」和「会运维作业」的分水岭**。

**本周出口**：亲手做一次故障恢复并验证状态接着算；能推演 Barrier 对齐；

**下午动手**

- 跑 `w3.KeyedStateJob`，确认状态**按 key 隔离**（sensor-0 和 sensor-1 各算各的）

**对照 / 日记**

- 用你熟悉的 Redis 做对照，写下 Flink 白送了你哪三件事：
  并发正确性、持久化、故障恢复

## D17–D18 · State TTL 与状态后端

**上午精读**

- [状态过期（TTL）](https://nightlies.apache.org/flink/flink-docs-release-2.3/zh/docs/dev/datastream/fault-tolerance/state/#state-time-to-live-ttl)
- [状态后端](https://nightlies.apache.org/flink/flink-docs-release-2.3/zh/docs/ops/state/state_backends/)：

**下午动手**

- 跑 `w3.StateBackendJob`，然后把 `USE_ROCKSDB` 改成 `true` 再跑一遍

**对照 / 日记**

- 自问：**什么时候必须上 RocksDB？**（答：状态大到快照做不出来时——
  它是唯一支持**增量 checkpoint** 的后端）

## D19–D20 · Checkpoint 与故障恢复

**上午精读**

- [Checkpointing](https://nightlies.apache.org/flink/flink-docs-release-2.3/zh/docs/dev/datastream/fault-tolerance/checkpointing/)：
  配置项、Barrier 对齐、Savepoint 与 Checkpoint 的区别
- 加深：搜一下 Chandy-Lamport 分布式快照算法，理解 Flink 快照的理论基础

**下午动手**

- 跑 `w3.CheckpointConfigJob`（作业约 6 秒，期间会做一次 checkpoint）
- 确认 checkpoint 文件真的落在了 `/tmp/flink-learning/checkpoints/`

**对照 / 日记（本周的核心 DoD）**

- **亲手做一次故障恢复**——这是整个项目里唯一需要你「动手破坏」才能学会的东西：
  1. 跑作业，记下某个 key 的累计条数
  2. Ctrl-C 杀掉
  3. 从 checkpoint 恢复重跑
  4. **确认累计条数接着上次继续，而不是从 1 重新开始**

  「接着数」才是恢复成功的证据。日志里出现「已恢复」不算。
- 另一个对照：把 checkpoint 间隔从 5 秒改成 1 秒再跑，观察快照频率对作业的影响
- DoD：能画图说明 Barrier 如何从 source 流到 sink，以及对齐（aligned）在做什么
