# 一手资料与官网

原则：**优先官方文档**。社区博客标为「二手」，适合补齐工程语境，不与一手混称。

怎么读这些站点：见 [Flink 怎么学 · 怎么读官方文档](./how-to-learn.mdx#怎么读官方文档)。

## 一个重要发现：官方中文文档是可用的

Flink 官方中文文档**仍在维护，且已覆盖 2.x**（nightlies 的 `/zh/` 目录持续构建）。
这意味着**不必依赖二手翻译**——这是本项目把中文官方文档作为主表的原因。

:::danger[版本陷阱：看任何资料前先确认版本]
Flink 2.x 与 1.x 的文档差异极大，而搜索引擎和博客里 **1.x 的资料仍然占多数**。
判断资料是否过时的快速信号：

- 出现 `addSource` / `addSink` / `SourceFunction` / `SinkFunction` → 1.x
- 出现 `DataSet` API → 1.x
- 出现 `env.setStateBackend(...)` → 1.x
- 出现 `flink-conf.yaml` → 1.x

具体差异见 [2.x 与 1.x 的破坏性差异清单](./how-to-learn.mdx#2x-与-1x-的破坏性差异清单)。
:::

## D. 怎么用这些资料

1. **Week 日程「必读」** → 优先 A / B 的官方链接。
2. **同周加深** → 需要工程语境时再翻 C，且先确认版本。
3. **遇到不确定的 API** → 直接看 javadoc 或反编译类，比搜博客快且准
   （本项目里 `env.setStateBackend` 已移除、`SourceReader.isAvailable()` 是新增抽象方法，
   都是这么确认的）。
4. **版本会变** → 涉及 API、连接器、JDK 版本时，以官网当日文档为准。

## 四周验收清单

- [ ] JDK 17 配好，`./run.sh mvn -B compile` 通过，能解释为什么不能用 JDK 25
- [ ] 说得出至少 4 条 2.x 的破坏性变更
- [ ] 能画清作业从 `main()` 到 TaskManager 的执行路径
- [ ] 手写过一遍 FLIP-27 Source，知道 Split / Enumerator / Reader 各管什么
- [ ] 能用 `keyBy` 解释「同一 key 必进同一并行实例」及其代价
- [ ] 能写出水位线公式，并**亲手跑出两种容忍度的对照差异**
- [ ] 说清四类窗口的差别，知道会话窗口为什么需要合并
- [ ] **亲手触发过窗口重算**，并知道下游该怎么应对
- [ ] 能解释 Keyed State 免锁并行的原理
- [ ] 用过 State TTL，说得出它的三个坑
- [ ] 能用新写法切换状态后端，说明什么时候必须上 RocksDB
- [ ] **亲手做了一次故障恢复，且验证状态接着算**（不是日志说恢复成功）
- [ ] 能推演 Barrier 对齐，分清 Checkpoint 与 Savepoint
- [ ] 用 Flink SQL 写出过窗口聚合，理解动态表与 changelog
- [ ] **端到端链路跑通**，能讲清两阶段提交如何保证不重、代价是什么
- [ ] 能列出线上必看指标，并对着 Web UI 判断作业有没有问题

未勾项按优先级排进第 2 个月，而不是同时开新项目。

## 第 2 个月预览

- **Flink CDC**：从数据库 binlog 直接入湖入仓，替代定时抽数
- **Paimon / Iceberg / Hudi**：流式数据湖，解决「实时链路的数据落哪」
- **状态调优进阶**：RocksDB 参数、增量 checkpoint 实践、状态迁移与扩缩容
- **Flink on Kubernetes**：Operator 部署、弹性伸缩、多租户
- **源码层**：`StreamTask` 执行循环、`CheckpointCoordinator`、网络栈与反压实现
- **Python / PyFlink**：如果团队里有数据科学同学要自己写作业
